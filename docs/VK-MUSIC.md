# VK Музыка в MidiPult: что сделано, что за приложение на dev.vk.com и почему музыки не будет

**Дата:** 21.11.2026
**Устройство:** Yandex Station Midi (Cucumber DVT2), панель в `/data/myweb`
**Статус:** провайдер VK в панели выключен («скоро»); этот документ объясняет, почему
его нельзя «просто доделать», и что делать вместо него.

---

## 1. Коротко

1. **Приложение на dev.vk.com музыку не даст.** ВКонтакте закрыл публичный audio API:
   методы `audio.*` работают только у «одобренных» приложений, а новым приложениям
   право `audio` не выдаётся.
2. **Кнопка «Войти через VK» в панели не заработает ни с каким Client ID.** Она построена
   на Implicit Flow (`response_type=token`), который VK отключил 25 июня 2024 года,
   и на redirect `http://<IP-станции>:8055/vk_oauth.html`, который VK ID не примет.
3. **Экран на скриншоте («Создание приложения без кода»)** — это конструктор
   мини-приложений для каталога ВКонтакте. К музыке и к станции он отношения не имеет.
4. **Что реально работает уже сейчас:** телефон → станция по Bluetooth (станция —
   A2DP-приёмник), плюс Яндекс Музыка, которая на станции авторизована.

Дальше — по шагам: что лежит в проекте, что именно произойдёт на dev.vk.com, где
именно ломается вход и какие есть рабочие обходные пути.

---

## 2. Что уже сделано в проекте

| Файл | Что делает | Чего не хватает |
|---|---|---|
| `cgi-bin/vk.py` | `audio.search`, `audio.get`, разбор трека, запуск через штатный плеер (`radio.play_stream`), токен в `/data/mypult/vk_token.json` (0600) | токена, у которого есть право `audio` |
| `cgi-bin/vk_stream.py` | прокси потока с поддержкой `Range`, чтобы плеер станции мог играть и перематывать | понимания, что в 2026 VK отдаёт не mp3-файл, а HLS (`.m3u8`) с AES-128 |
| `index.html` | вкладка «VK Музыка»: поле Client ID, кнопка «Войти через VK», показ Redirect URI, поле для вставки токена, поиск и «Моя музыка» | рабочего способа получить токен |
| `vk_oauth.html`, `vk_callback.html` | страницы возврата после OAuth: забирают `access_token` из `#` и передают в панель через `postMessage` | — |
| `README.md`, `docs/VK-MUSIC.md` | README ссылается сюда; история провайдера — в `CHANGELOG.md` | — |

Ключевые места в коде:

- `index.html` → `vkRedirectUri()` возвращает `location.origin + '/vk_oauth.html'`,
  то есть `http://192.168.1.216:8055/vk_oauth.html`;
- `index.html` → `vkOAuthStart()` собирает
  `https://oauth.vk.com/authorize?...&scope=audio,offline&response_type=token`;
- `cgi-bin/vk.py` → `_api()` ходит в `https://api.vk.com/method/` с токеном и `v=5.199`.

То есть в проекте уже написана вся «серверная» часть, и не хватает ровно одного
звена — **источника токена с доступом к аудио**. Именно это звено ВКонтакте и закрыл.

## 3. Почему dev.vk.com не поможет: пять фактов

### 3.1. Implicit Flow отключён с 25 июня 2024

Документация VK прямо перечисляет устаревшие способы:

> Authorization Code Flow … Отключён с 25 июня 2024 года.
> Implicit Flow … Отключён с 25 июня 2024 года.
> — <https://dev.vk.com/ru/api/access-token/getting-started>

Именно Implicit Flow (`response_type=token`, токен приходит в `#access_token=…`)
использует кнопка в панели. Для новых приложений он не работает: VK вернёт ошибку
ещё до экрана «Разрешить».

### 3.2. Методы `audio.*` закрыты для сторонних приложений

Публичный audio API ВКонтакте отключён; методы работают только у приложений,
которые VK одобрил вручную. Об этом до сих пор предупреждает официальный
хелпер токенов VK:

> методы для работы с аудиозаписями и сообщениями работают только с одобренными
> приложениями. Подробнее: «Отключение публичного API для аудио»
> — <https://vkhost.github.io/>

Проверка «жив ли метод» (21.11.2026, без токена):

```
GET https://api.vk.com/method/audio.get?v=5.199
→ {"error":{"error_code":15,"error_msg":"Access denied: token required"}}
```

Метод существует, но требует токен, которому разрешено аудио. У нового приложения
такого разрешения нет — в ответ придёт `error 15` (в `vk.py` это уже обработано
сообщением «токену VK не разрешён доступ к аудио»).

### 3.3. В VK ID нет права `audio`

Сервис авторизации VK ID (туда переехали все Standalone-приложения) даёт только:

| Право | Что даёт |
|---|---|
| `vkid.personal_info` | имя, фамилия, пол, фото, дата рождения |
| `email` | почта |
| `phone` | телефон |

Источник: <https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes>

Другие права (`friends`, `video`, `photos` и т. п.) — «в исключительных случаях»
по письму на devsupport@corp.vk.com. Аудио в этом списке нет вообще.

### 3.4. Standalone-приложения больше не создаются на dev.vk.com

Из документации VK ID:

> …настройка Standalone-приложений более недоступна. Это значит, что мы перенесли
> все ваши Standalone-приложения в сервис авторизации VK ID.
> — <https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application>

Там же — требования, которые убивают локальный redirect:

- нужен подтверждённый **профиль бизнеса** через VK Бизнес ID (иначе приложение
  блокируют);
- «Базовый домен» и «Доверенный redirect URL» должны совпадать по домену;
- `http` допускается только для `localhost:80`, остальные порты «временно
  не поддерживаются».

`http://192.168.1.216:8055/vk_oauth.html` не подходит ни по схеме, ни по адресу,
ни по порту.

### 3.5. Неофициальные клиенты ВКонтакте дожимают

С 7 сентября 2026 VK ввёл ежемесячные лимиты запросов и платный API для сторонних
сервисов. 10 сентября 2026 команда Kate Mobile объявила о прекращении работы
клиента — «новые условия VK API фактически поставили точку в существовании
неофициальных клиентов».

Источник: <https://gazeta.spb.ru/2666520-razrabotchiki-kate-mobile-soobshhili-o-blokirovke-dostupa-k-vk-api/>

Это значит, что и классический обход «взять токен Kate Mobile» больше не вариант:
таких токенов просто негде взять, а эмуляция официального клиента живёт до
следующего изменения API.

## 4. Что за экран на скриншоте и что будет, если нажать «Создать»

На скриншоте — `dev.vk.com` → «Приложения» → **«Создание приложения без кода»**.
Это конструктор **мини-приложения** (VK Mini Apps): название (до 34 символов),
категория («Образ жизни» и т. п.), кнопка «Создать».

Что произойдёт дальше:

1. VK попросит подтвердить действие (push или код в приложении VK);
2. откроется панель приложения, где будет **ID приложения** (`app_id`);
3. в настройках будут разделы «Информация», «Размещение», «Доступы», «Модерация» —
   и всё.

Чего там **не будет**:

- поля «Redirect URI» для внешнего сайта — мини-приложение открывается по адресу
  `https://vk.com/app{ID}` внутри ВКонтакте, в iframe;
- права `audio` в «Доступах»;
- возможности отдать станции поток: мини-приложение — это страница для VK-клиента,
  а не API для колонки.

Итог: `app_id` вы получите, но в панели MidiPult его некуда вписать так, чтобы это
заработало. Кнопка «Войти через VK» уйдёт на `oauth.vk.com` с отключённым
`response_type=token` и вернёт ошибку.

## 5. Если всё-таки идти в VK ID: пошагово

Это единственный «белый» путь, и он всё равно не даёт аудио. Порядок такой:

1. Открыть <https://id.vk.ru/about/business/go/>, войти через VK Бизнес ID.
2. Подтвердить профиль бизнеса (данные организации). Без этого приложение
   заблокируют, а ключи и настройки будут недоступны.
3. «Мои приложения» → «Добавить приложение».
4. Название → платформа **Web** → иконка.
5. «Базовый домен» — реальный домен, например `mypult.example.ru`.
   «Доверенный redirect URL» — `https://mypult.example.ru/vk_oauth.html`
   (домен должен совпадать с базовым; IP и порт 8055 не принимаются).
6. «Доступы» → только личные данные, почта, телефон. Аудио нет.
7. «Создать приложение» → в карточке появятся **ID приложения (client_id)**,
   **Защищённый ключ**, **Сервисный ключ доступа**.
8. В панели MidiPult: «Client ID» = ID приложения, «Redirect URI» = доверенный
   redirect URL.

Что произойдёт на практике: панель откроет `oauth.vk.com/authorize` со старым
Implicit Flow → ошибка. Если переписать вход на VK ID SDK (PKCE), токен вы получите,
но в нём не будет права `audio`, и `vk.py` вернёт «токену VK не разрешён доступ
к аудио».

**Вывод:** создавать приложение можно, но это не приблизит музыку ни на шаг.
Единственное, для чего оно пригодится, — вход по VK ID на стороннем сайте
(«Войти через VK»), а не музыка.

## 6. Рабочие варианты

### A. Bluetooth: телефон → станция (работает сегодня, рекомендуется)

Станция — A2DP-приёмник (`cgi-bin/bluetooth.py`, `bluealsad` → ALSA), то есть
выглядит для телефона как обычная Bluetooth-колонка.

1. Панель → карточка **Bluetooth**: кнопка «Bluetooth: выкл» → включить,
   затем «Сопряжение» → станция станет видимой для телефона (режим discoverable).
2. На телефоне: настройки Bluetooth → выбрать станцию (появится в списке).
3. Открыть VK Музыку на телефоне и играть — звук идёт на станцию.
4. Громкость и «стоп» можно делать с пульта: панель синхронизирует ALSA `Master`.

Плюсы: без токенов, приложений и банов; работает с любым телефоном.
Минусы: телефон занят, качество SBC/AAC, поиск и очередь — на телефоне.

Что стоит добавить в панель: на вкладке «VK Музыка» вместо мёртвой кнопки —
короткую инструкцию «включите Bluetooth и играйте из приложения VK Музыка»,
со ссылкой на карточку Bluetooth.

### B. Яндекс Музыка (уже авторизована)

На станции Яндекс Музыка авторизована, поиск/плейлисты/«Моя волна» работают.
Если нужные треки есть в Яндекс Музыке — это самый короткий путь.
Перенос плейлистов из VK автоматическими сервисами упирается в то же самое:
сервису нужен доступ к аккаунту VK.

### C. Неофициальный токен (если очень надо, с рисками)

Схема, которой пользуются загрузчики 2026 года: авторизация **по логину и паролю**,
как официальное мобильное приложение (библиотека `vkpymusic`), получение токена
с правом `audio`, затем `audio.get` / `audio.search`. Примеры:
<https://github.com/loloka/vk-music-downloader>,
<https://github.com/issamansur/vkpymusic>.

Что придётся сделать в MidiPult:

1. Модуль входа: логин/пароль (или одноразовый токен, добытый на ПК) → токен
   на станции. Пароль на станции — плохая идея, лучше вводить его в панели
   и не хранить.
2. Разобрать капчу и 2FA (интерактивно, через панель).
3. Переписать `vk_stream.py`: VK отдаёт HLS (`.m3u8`) с AES-128, а не mp3.
   Нужен прокси, который тянет плейлист, ключ и расшифровывает сегменты на лету.
   На A5 с 974 МБ RAM это заметная нагрузка.

Риски: капчи, лимиты, «нетипичный трафик» и, в пределе, блокировка аккаунта.
Kate Mobile закрылся именно потому, что VK выдавил неофициальных клиентов.

### D. Скачать свою фонотеку и залить на станцию

На ПК: `vk-music-downloader` (например, <https://github.com/loloka/vk-music-downloader>)
→ mp3 с тегами → загрузить в «Свои звуки» станции (в панели есть загрузка файлов
и проигрывание своих звуков). Минус: место на `/data` и ручное обновление.

## 7. Что предлагаю сделать в репозитории

1. Убрать из панели кнопку «Войти через VK», показ Redirect URI и текст
   «включите доступ к аудио» — они обещают то, чего VK не даёт.
2. Оставить вкладку «VK Музыка» с честной пометкой «недоступно: VK закрыл API»
   и кнопкой-подсказкой «Как слушать VK на станции» → карточка Bluetooth.
3. Обновить README (пункт про VK) и CHANGELOG.
4. Если решим идти путём C — отдельный план: модуль входа, HLS-прокси,
   обработка капчи, тесты на станции.
